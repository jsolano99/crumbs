## Stack

Next.js 16.3.2 (App Router, TypeScript, Turbopack), React 19. Plain CSS Modules — no Tailwind, no component library, no CSS-in-JS. Model provider is **OpenAI** (`gpt-4o-mini`, chosen explicitly for low per-request cost — not Anthropic). Auth is hand-rolled (bcrypt + cookie sessions), not NextAuth/Clerk. Persistence is Upstash Redis via `@upstash/redis`. Deploy target is Vercel.

## Architecture

**The §§ protocol** (`src/lib/parse-breakdown.ts`, `src/app/api/breakdown/route.ts`): the model responds with plain-text `§§CORE` / `§§TERMS` / `§§STEPS` / `§§END` markers, not JSON, so the raw stream can be parsed incrementally as bytes arrive. `parseBreakdown(raw, { complete })` is safe on a partial buffer; its "no markers found — treat as core" backstop only fires when `complete: true` (i.e. `phase === "day"`), never mid-stream, so it can't misfire on an early chunk that hasn't finished forming a marker yet. Don't change the delimiter format without updating the system prompt and the parser together.

**Dawn Cyclorama** (full spec in `DESIGN.md`): the page background literally transitions night → first-light → dawn → day (or → blackout on error), bound to real fetch lifecycle state, never a timer. `.stage[data-phase]` drives it. Five gradient layers share one `.backdrop`; every layer but blackout shares a 1.3s crossfade, blackout gets a deliberately abrupt 0.15s cut — that asymmetry is intentional, not a bug. Reuse this world for new UI (Ember accent for new controls per the system's own "Ember Constant Rule", paper/ink for cards, Allerta Stencil only for small tracked-caps labels, never body copy).

**SwipeDeck** (`src/app/SwipeDeck.tsx`): tinder-style card stack for the *completed* breakdown — real pointer-drag physics (distance + velocity threshold, 1:1 live tracking mid-drag, transition-based fling-out/spring-back on release). Only renders once `phase === "day"`; while still streaming, `page.tsx` renders a simpler stacked reveal instead. Term cards link each defined term to a "Tell me more about X" search in a new tab (`learnMoreUrl`) — the drag handler explicitly ignores pointerdown when the target is inside an `<a>`, or link clicks get swallowed by the swipe gesture.

**Tweet/Article URL resolution** (`src/app/api/breakdown/route.ts`), three layers in order:
1. `fetchTweetTextViaFxTwitter` (`src/lib/fxtwitter.ts`) — primary. FxTwitter's free public extraction API (`api.fxtwitter.com`), a purpose-built X data layer, not a generic page renderer. The only one of the three that can read X **Article** (long-form post) bodies, via `tweet.article.content.blocks`.
2. `fetchTweetTextFromUrl` (`src/lib/tweet-oembed.ts`) — fallback for regular tweets if FxTwitter is unreachable. X's official public oEmbed endpoint, free/unauthenticated, but does **not** expose Article bodies (only a bare `t.co` link).
3. Honest refusal — if both fail, or the "resolved" text is itself still just a URL. **Never remove this backstop or let the model guess at content that wasn't actually resolved** — see `PROJECT_STATE.md`'s fabrication incident.

**Auth & quota** (`src/lib/auth.ts`, `src/lib/rate-limit.ts`, `src/lib/anon.ts`): email+password (bcrypt cost 12), httpOnly session cookie → Redis. Anonymous visitors get one free breakdown, tracked via a persistent httpOnly device cookie (`crumbs_anon_id`) checked server-side against Redis — **not** client-side storage, so it survives closing/reopening the tab. Backstopped by a per-IP daily cap on how many free tries can be granted at all. Signed-in accounts get a generous daily cap instead of a hard 1-try limit. Everything here fails open when Redis isn't configured (see Env vars above) rather than breaking the app.

## Conventions

- CSS Modules only, in `page.module.css`. Reuse existing color/spacing/radius tokens before inventing new ones — the impeccable design-system detector hook flags undocumented literals on every edit; a legitimate one-off gets an explicit `ignore-value` entry in `.impeccable/config.json` with a written reason, never a silent pass.
- `/api/breakdown` streams `text/plain`, not SSE/JSON — client reads the raw body via `ReadableStream` + `TextDecoder`, matching the §§ protocol above.
- Any server-side fetch built from a user-supplied URL must target a fixed, trusted host, never the user's raw URL directly (see how `fxtwitter.ts`/`tweet-oembed.ts` parse out a handle/id or pass the URL only as a query param to their own trusted endpoint) — this avoids SSRF by construction.

## Known gotchas

- The Claude_Browser screenshot tool has a real artifact: capturing a *scrolled* position on a page taller than the viewport can render fixed/absolute background layers as a solid black gap that isn't real. Confirmed via `getComputedStyle`/`getBoundingClientRect()` before ever treating this as a shipped bug — resize the viewport tall enough to avoid scrolling, or measure via JS, first.
- `position: fixed` full-page background layers are unreliable in practice — one real shipped bug here was exactly this. Use `position: absolute` on a `position: relative` parent for full-page atmosphere layers instead (`.backdrop` does this now).
- A subagent (the DESIGN.md documenter, during the initial finish pass) once made an unauthorized UI change outside its documentation-only mandate — it converted the state-cue pill from inline to `position: fixed` and shipped a mobile overlap bug in the same move. The fixed-position pill is now the kept, intended design (bug fixed same-session) — noted here only so its origin isn't a mystery later.
